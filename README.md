# BROVA — ระบบหลังบ้าน

ระบบจัดการงานผลิตเสื้อ ตั้งแต่ลูกค้าทักเข้ามาจนปิดงานและเก็บเงินครบ
สร้างด้วย Next.js 14 และ Supabase

**เริ่มที่ [DEPLOY.md](./DEPLOY.md)** ถ้าจะเอาขึ้นใช้งานจริง

---

## ระบบนี้ทำอะไรให้

**งานไม่หายกลางทาง** สถานะภายใน 24 ขั้น พร้อมประตูตรวจ 8 บาน
ที่กั้นไม่ให้ข้ามขั้นตอนสำคัญ เช่นห้ามเข้าไลน์ผลิตก่อนลูกค้าเคาะแบบ
ห้ามแพ็กของที่ยังไม่ตรวจคุณภาพ ห้ามปล่อยของก่อนเก็บเงินครบ

**เรื่องนอกกรอบต้องผ่านเจ้าของ** ลดราคาเกินเพดาน เลื่อนกำหนดชำระ ส่งของก่อนชำระครบ
ข้ามประตู ยกเลิกงาน หรือซื้อเกินงบ ทั้งหกเรื่องนี้ระบบบังคับให้ขออนุมัติก่อน
ไม่ได้เตือนเฉย ๆ แต่ทำรายการไม่สำเร็จจริง ๆ จนกว่าเจ้าของจะกดอนุมัติ

**เอกสารออกจากระบบเดียวกัน** ใบเสนอราคา ใบวางบิล ใบเสร็จ ใบลดหนี้
แก้ได้ทุกคำบนใบตอนเป็นร่าง ออกเลขแล้วล็อกถาวร คิดภาษีมูลค่าเพิ่มและหัก ณ ที่จ่ายให้อัตโนมัติ

**สต็อกอธิบายที่มาได้ทุกตัว** รับของจากใบสั่งซื้อ จองผ้าให้งาน ปรับยอดตามผลนับ
ทุกการขยับบันทึกยอดก่อนและหลังไว้ ลบไม่ได้

**ลูกค้าดูความคืบหน้าเองได้** ลิงก์เฉพาะของแต่ละงาน เห็น 7 ขั้นที่เข้าใจง่าย
โดยไม่เห็นต้นทุน กำไร ชื่อโรงงาน หรือข้อมูลลูกค้ารายอื่น

**แจ้งเตือนเข้าไลน์เป็นการ์ด** เก้าเหตุการณ์ ตั้งได้ว่าเรื่องไหนเข้ากลุ่มไหน
พร้อมสรุปประจำวันส่งอัตโนมัติทุกเช้า

**ตั้งบัญชีและเพิ่มทีมได้ในระบบ** บัญชีแรกได้สิทธิ์เจ้าของอัตโนมัติ
เจ้าของเพิ่มคน แก้บทบาท และตั้งรหัสผ่านใหม่ให้คนที่ลืมได้เอง

**มีคู่มือในตัว** 21 หัวข้อ ค้นหาภาษาไทยได้ เปิดจากปุ่มคู่มือบนแถบเมนูได้ทุกหน้า

## โครงไฟล์

```
supabase/          สคริปต์ฐานข้อมูล รันตามลำดับเลข 01 ถึง 10
                   11_go_live.sql รันตอนพร้อมเลิกใช้ข้อมูลตัวอย่าง
                   dev_*.sql เฉพาะเครื่องทดสอบ ห้ามรันบน Supabase

src/lib/           แกนกลางของระบบ
  workflow.ts        สถานะงาน ประตูตรวจ กลุ่มผ้า เรื่องที่ต้องขออนุมัติ
  accounting.ts      กติกาภาษีและการล็อกเอกสาร
  doc-model.ts       รูปแบบข้อมูลกลางของเอกสารทั้งสามใบ
  format.ts          วันที่แบบไทย จำนวนเงินเป็นตัวอักษร
  rules.ts           เพดานที่เจ้าของตั้งไว้
  manual.ts          คู่มือการใช้งานที่เปิดอ่านได้ในระบบ
  line/flex.ts       การ์ดแจ้งเตือนเข้าไลน์ทั้งเก้าแบบ
  line/send.ts       ส่งเข้าไลน์ พร้อมลองซ้ำและบันทึกประวัติ

src/actions/       งานฝั่งเซิร์ฟเวอร์ ทุกกติกาบังคับที่นี่ ไม่ใช่ที่หน้าจอ
src/components/    ชิ้นส่วนหน้าจอที่ใช้ร่วมกัน
src/app/           หน้าจอทั้งหมด
  (app)/             หน้าที่ต้องล็อกอิน
  track/[token]/     หน้าที่ลูกค้าเปิดดูได้โดยไม่ต้องล็อกอิน
```

---

## หลักที่ยึดตอนเขียน

**กติกาอยู่ที่เซิร์ฟเวอร์ ไม่ใช่ที่หน้าจอ** หน้าจอบอกล่วงหน้าว่าจะติดอะไร
แต่คนตัดสินคือเซิร์ฟเวอร์และฐานข้อมูล ต่อให้แก้ HTML ในเบราว์เซอร์
หรือยิงคำสั่งตรงเข้าฐานข้อมูล กติกาก็ยังอยู่

**สิ่งที่เกิดขึ้นแล้วห้ามหายไป** เอกสารที่ออกเลขแล้ว การรับเงิน การเคลื่อนไหวสต็อก
และใบขออนุมัติ ทั้งหมดลบไม่ได้ แก้ผิดพลาดด้วยการออกรายการใหม่ที่หักล้างกัน

**หน้าสาธารณะต้องเห็นน้อยที่สุด** หน้าติดตามงานของลูกค้าดึงข้อมูลผ่านฟังก์ชัน
ที่คืนเฉพาะฟิลด์ที่ปลอดภัย ไม่ได้กรองที่หน้าจอ ฟิลด์ที่ไม่ควรเห็นจึงไม่มีทางหลุด
